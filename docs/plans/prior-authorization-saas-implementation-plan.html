1. Executive Summary

This plan defines how to build a FHIR-native Prior Authorization SaaS service that can be deployed as a managed service on any major cloud — AWS, Azure, or GCP — and consumed by provider EMRs via CDS Hooks and SMART on FHIR. The service replaces IBM's existing watsonx-chatbox-driven PreAuth Portal with a fully standards-conformant implementation of three HL7 Da Vinci implementation guides: Coverage Requirements Discovery (CRD), Documentation Templates and Rules (DTR), and Prior Authorization Support (PAS).

Work begins on an existing, load-bearing foundation: the rickwill-ibm/rhtp-fhir-poc repository already contains three completed branches — phase1 (FHIR server + identity), phase2 (live FHIR data), and phase3 (live data wired to all pages). All new work occurs on a new branch: feature/phase4-crd-dtr-pas-integration.

The build runs 18 calendar weeks across six execution phases plus a hardening sprint. The total estimated implementation cost is ~$882K with an ongoing steady-state run-rate of ~$49K/month ($587K/year).

2. End-State: What We Are Building

The end state is a cloud-portable, containerized, FHIR-native Prior Authorization microservice platform. It is multi-tenant by design, embeddable in any CDS-Hooks-compatible EMR, and deployable to AWS, Azure, or GCP using cloud-agnostic container orchestration (Kubernetes / ECS / ACA). Below is the full service topology.
