5. Maturity Ceiling — Honest Assessment

The build sandbox has no Docker. Every component whose correctness depends on real Postgres multi-writer semantics, real Neo4j Cypher execution, real Temporal worker behavior, or real Kafka partition ordering is green on fakes but unproven on live infra. This is a known, documented ceiling recorded in docs/BUILD_LESSONS_AND_ROADMAP.md (L1/L5) and the individual FAKE_FIDELITY.md files. The second progress counter — "components live-proven on real infra" — is currently 0. This does not mean the code is wrong; it means the proof is deferred to CI with Docker (all testcontainer specs already authored and waiting).

6. Critical Path (Recommended Sequencing)

  • Next (I5): Care-team + workflow record domains — highest-throughput progress available; continues proven domain-template pattern.
  • I6: Sensitive/financial domains — Part 2 compliance risk; must precede any behavioral-health operational use.
  • I7: Network adequacy view-model consolidation (independent; can interleave with I5/I6).
  • I8A: Terminology + external identity + value-set governance — XL; run as three back-to-back sub-iterations; most valuable after I6 lands behavioral/social domains.
  • I8: Care plan depth + clinical criteria — gated on clinical SME calendar (GB-3).
  • I9: Real execution substrate (Kafka, Temporal, IaC) — gated on cloud accounts; all prior testcontainer specs become runnable.
  • I10: Certification pass — last; cannot honestly run earlier (live backbone, pen-test, conformance calendar all required).
