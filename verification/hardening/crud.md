# CRUD-Completeness Hardening Findings

Role: CRUD-completeness adversary (R1 domain-fidelity + R2 negative-space). Read-only review of
`/home/claude/baseline` (iterations 1-11). Lens: for every major entity, does a real payer/HIE
deployment have the CREATE / READ (incl. history + as-of) / UPDATE-correct-amend / VOID-entered-in-error /
DELETE (soft-delete/tombstone with the right immutability + retention + right-to-delete) it needs, with
authz, or is the entity write-once / one-directional / missing an editable surface entirely?

Method: tree-of-thought, one branch per entity (member/identity, coverage, consent directive, provider
identity, value-set version, care plan, claims, the 20 WpcDomain records, dead-letter, evidence, golden
record). Findings are gaps that block or degrade a production deployment, whether or not the GAP register
already names them; the register's own deferral is cited where relevant (a deferred gap is still a gap for
deployment). Verified against source: the BFF exposes only GET/POST across `src/app/api/**` (no PUT / PATCH
/ DELETE handler exists anywhere), and several lifecycle engines exist in `src/lib/**` with no HTTP surface.

## Cross-cutting observations

- The single largest structural gap is that the platform is **write-once at the HTTP surface**: `app/api/**`
  exposes GET + POST only. Every "correction" story (CRUD-02, -06, -07, -14) traces back to there being no
  UPDATE/VOID verb reachable by an operator, steward, or member. Several correct lifecycle engines exist in
  `lib/**` (lifecycle right-to-delete, xref merge/unmerge) but are **stranded without an API surface**
  (CRUD-03, -05).
- Immutability rules that ARE present are correct and should not be "fixed" into hard-deletes: the evidence
  ledger and dead-letter store are append-only with DB triggers, and right-to-delete is a governed tombstone
  that preserves prior versions. The gaps are the *missing* editable/reversible surfaces around them, not the
  append-only rule.
- Authz for the write paths that do exist is attributed (consent requires `recordedBy`; dead-letter actions
  and VSG maker-checker are gated), so the CRUD gaps are about *absent operations*, not unguarded ones.
