# Security & Multi-Tenancy Hardening Review — CMS-0057-F Payer Platform

Adversarial (red-team) review for DEPLOYMENT robustness against a US-healthcare-payer
security review. Read-only: findings only, no source modified. Reasoning branched
across the OWASP API Security Top 10 + tenant isolation + secrets + supply-chain.

Scope reviewed: `src/lib/authz/**`, `src/lib/server/**` (smartSession, env, fhirServer,
log, correlation, devStubs), the BFF routes under `src/app/api/**` (esp. the FHIR
passthrough `src/app/api/fhir/[...path]/route.ts`), `src/lib/config/{dataMode,seamDispositions,appConfig}.ts`,
`src/lib/runtimeConfig.ts`, consent/Provider-Access authz, `src/middleware.ts`,
`package.json` / `package-lock.json`.

Verdict: **Would NOT pass a payer security review as-is.** The single largest gap is
the total absence of any tenant / plan / line-of-business boundary: the platform is
built for a payer running Medicaid MCO + MA + Commercial and multiple client health
plans, yet no plan boundary is enforced in identity, authz, stores, or the BFF. A
reviewer-class principal is org-wide by construction, and clinical FHIR reads carry no
per-member scope at all.

## Cross-cutting notes

- **What already fails closed (credit where due):** the session-secret resolution
  (`requireSessionSecret`, R5) throws in production with no public default; dev-mock
  auth double-gates on `!tokenUrl && ALLOW_DEV_MOCK_AUTH` (U1); no secrets use the
  `NEXT_PUBLIC_` prefix (only feature flags + a demo member id do); the dead-letter ops
  queue is correctly `isOpsPrincipal`-gated; the value-set-governance approve route
  enforces maker-checker at the boundary. These are the pattern the PHI + tenancy
  surfaces should adopt.
- **The tenancy gap is architectural, not a per-route patch.** S-01/S-03/S-10/S-13/S-14
  all trace to the same missing primitive: a `tenantId`/`planId` on the principal, on
  `MemberScope`, on every store key, and as a mandatory BFF filter. It should be one
  owning iteration.
- **Two parallel "mock" gates** exist (`devMockEnabled()` = auth-fail-closed vs
  `getDataMode()` = fail-open-to-mock) plus a legacy `appConfig.useMockData`. The
  divergence is itself a misconfiguration risk (S-14).
